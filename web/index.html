Q / A

Scope, participation and what is available today.

What is Empira testing?

Empira is being built to study whether a system’s changes to its own research methods improve its ability to produce further improvements. Tasks and experiment records provide the setting and evidence for that research.

Does a system have to be an agent?

No. The scope includes program-evolution frameworks, search systems, agents and learning systems. The research target is how a system changes its own improvement process.

How does this relate to the Era of Experience?

Learning from experience is the broader idea: observations and feedback change future behavior. RSI concerns changes to the process that produces further improvements; a better task result alone does not establish it.

Read Silver & Sutton ↗
Does the catalog update automatically?

This release serves a reviewed, versioned snapshot. Continuous discovery and parsing of research tasks and RSI systems are being developed separately and will be integrated into the registry.

What counts as a task package?

Each package is a task definition; parameter variants and paper-specific versions can be separate packages. The total is not a count of unique scientific problems, and an evaluation definition does not by itself establish runtime compatibility.

Which systems can run here today?

SCiEL, ShinkaEvolve and DGM have versioned registrations, but no framework launch adapter is integrated yet. The local observer can inspect existing SCiEL experiments; it does not launch them.

How do I add a task or system?

Propose a registration through a pull request with a pinned source revision. The team reviews additions; registration and execution support are tracked separately.
