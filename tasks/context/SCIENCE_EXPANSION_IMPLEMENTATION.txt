# Science expansion: implementation and validation

Recorded 2026-09-20T19:49:18+00:00. All **60 approved proposals** are represented: **56 new families, three existing-family upgrades and one existing-family reuse**. The catalog grew from the proposal snapshot's 903 to **959 canonical packages**.

Fresh generated-package execution receipts currently contain **45 passing seeds**, **15 source/setup blockers**, **0 failed runs**, and **0 missing or stale checks**. Passing means an actual source-data or declared scientific/mathematical-model run returned a finite score and explicit validity. Unit fixtures are excluded. **The remaining source/forward-model blockers are unfinished work; the expansion is not fully source-validated.**

## What was audited and added

The approved roadmap remains an unchanged historical proposal. Candidate artifacts, scientific questions and evaluation contracts were compared with existing packages before adding families. B04 upgrades the Station single-cell package; P05/P06 upgrade the existing particle-physics proxies; T02 reuses the Ramsey verifier. No new task is created by merely changing a source instance, graph size, region or material. The two old text-classification tasks labeled finance are corrected to language.

Every proposal has a canonical manifest, candidate contract, initial program with an EVOLVE-BLOCK, generated evaluator, SCiEL configuration, attributed source links, requirements, limitations and contribution/domain/data/verification labels. Data preparation is explicit; evaluation has no automatic source download or fabricated-data fallback. Scientific engines and source data are attributed separately from local evaluator authorship.

Implemented definitions, declared readiness, regression tests, actual seed runs and full-paper reproduction are different claims. These are bounded research adaptations; none is promoted to a published-score reproduction by passing its seed. Missing isotope/seismic forward models in particular still require implementation and scientific cross-checks.

## Dashboard statistics

The existing dashboard now has a **Statistics** navigation page at `/statistics` and downloadable data at `/api/statistics`. It reads canonical manifests rather than counting merged source records as extra tasks. Topic counts use the primary `area` label; climate dynamics remains a distinct topic from the added Earth/environment area.

“Reused upstream” means the active evaluator has the `original` protocol; “built here” includes `recreated` and `recreated_verified`. This is implementation authorship, not whether the paper had an available repository. Locally authored objectives can use upstream scientific engines, which are disclosed in task provenance. Unsupported and unknown origins remain separate.

**Important to science** requires a substantive scientific or real-world problem and a paper whose main research objective is solving it or advancing understanding of it. Merely evaluating an agent/framework on the task, or citing only a benchmark, dataset, or tool, does not qualify. The `science_relevance` record explains the underlying problem, why it matters, each cited paper's main objective, and the local task's connection. `labels.important_to_science` follows this evidence. Unreviewed tasks are not silently treated as unimportant. Contribution tiers and execution readiness remain separate axes; a measured dataset or a high score alone does not establish novelty or a new discovery.

Implementation counts, manifest readiness and recorded seed passes are separate. The page uses the latest saved attempt, excludes fixture-only records and invalid/nonfinite scores, and invalidates receipts when their recorded protocol or file hashes change. Older reports without complete hashes remain historical evidence, not certification of the current environment. Topic and count links open the corresponding library filters.

```sh
python3 run.py dashboard
```

Run the preparation commands in each domain document before expecting a fresh machine to pass source-dependent checks. Large raw files and isolated scientific environments are local caches, not redistributable repository assets. Source manifests retain URLs, preprocessing choices and hashes; honor their data terms. Public development instances and same-user candidate execution do not provide a secret held-out benchmark or a malicious-code sandbox.
