# Science supplement: eighteen tasks in six fields

Added on 2026-09-20 after reviewing the task catalog, shared evaluator families, manifest schema, catalog/suite generators, runner and SCiEL interface; eight more tasks (theoretical computer science, cosmology with real data, computational chemistry) were added the same day. The original 98-paper corpus remains unchanged; six supplemental source collections contain these eighteen additions.

Theoretical computer science and cosmology/astrophysics address the requested gaps. Particle physics, quantum information and climate dynamics are the three additional topics. They were chosen for substantive research questions with small, deterministic CPU evaluation protocols and independently checkable outputs. CERN's public challenges motivate the particle-physics tasks; the local synthetic events are explicitly distinguished from CERN datasets.

## What scores establish

The six TCS tasks are finite extremal construction problems on open questions (optimal sorting-network sizes for 16 to 18 wires, A(17,6) and A(18,6), the longest snake in Q_9, and R(5,5)). Tests independently verify a published 60-comparator network and a 512-word extended quadratic-residue code. The latter is constructed from the generator in [ETSI TS 102 361-1 V2.3.1, Annex B.3.2](https://www.etsi.org/deliver/etsi_TS/102300_102399/10236101/02.03.01_60/ts_10236101v020301p.pdf), extending rather than shortening it. They use `recreated_verified`, `open_problem`, `data=none`, `verification=exact`. Improving a weak seed or reproducing a known construction is not a new bound; any record claim requires comparison with current literature.

The Pantheon+ task is the one `discovery` task of the supplement: it fits real measurements (fetched by `scripts/prepare_science_data.py` from the public release at a pinned commit, never redistributed), and a better chi-squared than LambdaCDM is only meaningful together with the parameter count it reports. The two Lennard-Jones tasks are `recreated_verified` `method` tasks: the Cambridge Cluster Database minima are putative, reproduced in `tests/test_science_chemistry.py`. The other eight tasks use `recreated` and `method`. Their fixed small protocols are independently written adaptations of equations or challenges, not reproductions of paper scores. Cosmology tests approximate known equations on synthetic backgrounds. Particle events are illustrative toy samples, not a detector simulation or a discovery significance calculation. Quantum tests use ideal classical statevector simulation. Climate tests use nondimensional Lorenz models, not observed weather. In particular, low offline closure error need not produce stable online forecasts.

Every task specifies a candidate API, objective direction, seed, parameters, dependencies, source locators and limitations. `combined_score` is the raw score for maximization and its negation for minimization. Invalid candidates receive the existing failure envelope, not a valid zero score. Candidate-reported objective values are never trusted.

Evaluation cases are deterministic and public. Numerical tasks use separate calibration/training cases where applicable; those splits are not secret holdouts. SCiEL can inspect local code, so publication-quality generalization claims require freezing the candidate and evaluating fresh seeds or parameter regimes. The ordinary local evaluator process is not a security sandbox against malicious Python that modifies the checker.

## Storage and regeneration

- Reviewed definitions: `catalog/science/{tcs,cosmology,particle,quantum,climate,chemistry}.json`.
- Real data: `python3 scripts/prepare_science_data.py` fetches the Pantheon+ files (pinned commit, SHA-256) into `suite/_lib/data/pantheon-plus`.
- Importer: `scripts/import_science.py`, called by `scripts/build_catalog.py`.
- Family registration and seed templates: `scripts/science_<topic>.py`, loaded by `scripts/suite_families.py`.
- Shared scoring code: `suite/_lib/autoresearch_suite/science_<topic>.py`.
- Generated packages: `suite/science-*/`, with the same six files as existing tasks.
- Provenance pages: `papers/science-<topic>.md`; catalog JSON/CSV/HTML and `suite/index.json` include all eighteen tasks.
- Area labels: `theoretical_computer_science`, `cosmology_and_astrophysics`, `particle_physics`, `quantum_information`, `climate_dynamics`, `chemistry`.

```sh
python3 scripts/build_catalog.py
python3 scripts/build_suite.py --only '^science-'
.cache/sciel-env/bin/python scripts/check_science.py
python3 scripts/build_suite.py --only '^science-'  # incorporate measured cost labels
python3 scripts/task_labels.py --doc
python3 run.py validate
.cache/sciel-env/bin/python scripts/check_schema.py
.cache/sciel-env/bin/python -m unittest discover -s tests -p 'test_science_*.py'
.cache/sciel-env/bin/python -m unittest discover -s tests -p 'test_recreated_families.py'   # new TCS verifiers, Pantheon+ fit
```

Filtered suite regeneration now updates the global suite index, so adding a supplement does not leave the index stale. Existing tasks are preserved.

## Validation and running

[Seed results](../validation/science-report.md) and [machine-readable evidence](../validation/science-report.json) record the first ten process-isolated seed evaluations plus SHA-256 hashes; the eight later additions were run through the main harness (`validation/suite-report.json`) of definitions, templates, evaluators, seeds and scoring code. No model API, GPU, credential, data download or paid run is needed; NumPy and SciPy suffice.

[Integration checks](../validation/science-checks.json): all eighteen seeds valid; registry and schema validation pass; no duplicate groups; 295 regression tests run, with 264 passing and 31 existing environment-dependent skips. TCS and cosmology smoke runs also pass through the real SCiEL evaluator bridge. Regenerating the supplement and indexes produces identical contents across 66 checked files.

Independent tests cover exact reference constructions, analytic cosmology limits, a second growth reference, quantum dense-matrix exponentials and analytical spectra, particle label-permutation invariance and ranking ties, climate energy balance and periodic boundaries, RK4 convergence and a second ODE solver. Malformed, nonfinite, out-of-domain and incorrect candidate outputs are rejected. Baseline-improvement checks demonstrate useful search space without asserting that a fit always generalizes: unregularized degree-five closure can perform worse than the linear seed in the unseen forcing regime.

```sh
python3 run.py list --label area=theoretical_computer_science
python3 run.py list --label area=cosmology_and_astrophysics
python3 run.py evaluate science-particle-helical-track-reconstruction
python3 run.py evaluate science-quantum-qaoa-maxcut --candidate /absolute/path/candidate.py
```

SCiEL consumes each generated `initial_program.py`, `evaluator.py` and `config.yaml` directly. The existing `run.py experiment` command works with the new IDs and its usual model and budget settings; seed validation does not claim that model-driven evolution has been run.
